---
title: "Connectors"
description: "Automatically sync data from third-party applications like Slack, Gmail, Notion, GitHub, and Linear, enabling continuous ingestion without custom integration code."
---

Connectors let you sync data from third-party applications directly into HydraDB. Configure a connector once, and HydraDB handles authentication, pagination, and incremental syncing.

Use connectors when you want to:

- Ingest Slack messages, Gmail emails, or Notion pages automatically
- Sync GitHub issues from repositories for searchable project context
- Sync Linear issues from teams or projects
- Keep HydraDB in sync with external data sources on a schedule
- Avoid writing custom polling or webhook infrastructure

## Supported providers

| Provider | Data synced | Authentication |
|---|---|---|
| **Slack** | Messages from selected channels | Bot token (`xoxb-`) or user token (`xoxp-`) |
| **Gmail** | Emails from selected labels | OAuth token with `gmail.readonly` scope |
| **Notion** | Pages from selected databases or top-level pages | Internal integration token |
| **GitHub** | Issues from repositories (not pull requests) | Personal access token (`ghp_`) |
| **Linear** | Issues from selected teams or projects | API key (`lin_api_`) |

---

## How connectors work

A connector is a link between HydraDB and an external application. You provide credentials (an API token or OAuth secret), select which resources to sync (such as Slack channels, Gmail labels, or Notion databases), and HydraDB handles the rest.

```mermaid

  B --> C[Discover Resources]
  C --> D[Create Resources]
  D --> E[Sync Runs]
  E --> F[Data in HydraDB]

  style A fill:#0f172a,stroke:#334155,stroke-width:2px,color:#f8fafc
  style B fill:#0f172a,stroke:#334155,stroke-width:2px,color:#f8fafc
  style C fill:#4c1d95,stroke:#8b5cf6,stroke-width:2px,color:#ffffff

  style F fill:#0f172a,stroke:#10b981,stroke-width:2px,color:#f8fafc
```

Each connector has:

| Component | Description |
|---|---|
| **Provider** | The external application (Slack, Gmail, or Notion) |
| **Credentials** | Authentication for the provider (API token, OAuth, or client secret) |
| **Resources** | Individual data sources within the provider (Slack channels, Gmail labels, Notion databases) |
| **Sync schedule** | How often HydraDB pulls new data (default: 30 minutes) |

---

## Connector vs app sources

Connectors and [app sources](/essentials/app-sources) serve different purposes:

| Approach | When to use |
|---|---|
| **Connectors** | HydraDB pulls data automatically from a supported provider |
| **App sources** | You push data to HydraDB from your own backend or a provider we don't yet support |

Connectors produce app-source records internally. Once synced, connector data is searchable via `search_apps: true` just like manually ingested app sources.

## Setting up a Slack connector

You can set up a Slack connector using the dashboard or the API.

### Using the dashboard

The dashboard provides a visual interface for connecting Slack workspaces and selecting channels to sync.

#### 1. Navigate to Connectors

Open the dashboard at [app.hydradb.com](https://app.hydradb.com) and select **Connectors** from the sidebar.

#### 2. Connect your Slack workspace

Enter your Slack credentials in the connection form:

| Field | Description |
|---|---|
| **Tenant** | Select which tenant this connector belongs to |
| **Bot Token / User Token** | Your Slack token (starts with `xoxb-` for bot tokens or `xoxp-` for user tokens) |
| **Account scope** | Optional workspace identifier for multi-workspace setups |

Click **Connect** to create the connector.

<Tip>
Use bot tokens (`xoxb-`) for most integrations. User tokens (`xoxp-`) can access more channels but represent a specific user's permissions. Create bot tokens at [api.slack.com/apps](https://api.slack.com/apps) with the scopes listed below.
</Tip>

#### 3. Add channels to sync

Expand the connector row and click **Add** to open the channel picker. The picker shows all channels the bot can access.

Select channels to sync, then choose a sub-tenant mapping:

| Option | Behavior |
|---|---|
| **Per channel** | Each channel becomes its own sub-tenant (named after the channel) |
| **Single sub-tenant** | All selected channels share one sub-tenant you specify |

Click **Add channels** to start syncing.

#### 4. Manage your connector

From the connectors table you can:

- **Trigger sync** — Start an immediate sync instead of waiting for the schedule
- **View resources** — Expand a connector to see synced channels
- **Remove channels** — Delete individual channel resources
- **Delete connector** — Remove the connector and all its resources (synced data remains in HydraDB)

### Using the API

For programmatic setup or automation, use the Connectors API directly.

### 1. Create a Slack app

1. Go to [api.slack.com/apps](https://api.slack.com/apps) and create a new app.
2. Under **OAuth & Permissions**, add these bot token scopes:

| Scope | Purpose |
|---|---|
| `channels:read` | List public channels |
| `channels:history` | Read messages from public channels |
| `groups:read` | List private channels the bot is in |
| `groups:history` | Read messages from private channels |

3. Install the app to your workspace.
4. Copy the **Bot User OAuth Token** (starts with `xoxb-`).

### 2. Create the connector

```bash cURL
curl -X POST 'https://api.hydradb.com/v2/connectors' \
  -H "Authorization: Bearer $HYDRADB_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "slack",
    "tenant_id": "my_tenant",
    "auth_type": "api_token",
    "credentials": {
      "api_token": "xoxb-your-slack-bot-token"
    }
  }'
```

The response includes a `connector_id` you'll use for subsequent calls.

### 3. Discover available channels

Before adding resources, discover which channels the bot can access:

```bash cURL
curl 'https://api.hydradb.com/v2/connectors/<connector_id>/discover' \
  -H "Authorization: Bearer $HYDRADB_API_KEY"
```

**Response:**

```json
{
  "channels": [
    {
      "id": "C01ABC123",
      "name": "general",
      "is_private": false,
      "is_member": true,
      "num_members": 42
    },
    {
      "id": "C02DEF456",
      "name": "engineering",
      "is_private": false,
      "is_member": true,
      "num_members": 15
    }
  ]
}
```

<Note>
The bot must be a member of private channels to see them in the discover response. Invite the bot to any private channels you want to sync.
</Note>

### 4. Add channels as resources

For each channel you want to sync, create a resource:

```bash cURL
curl -X POST 'https://api.hydradb.com/v2/connectors/<connector_id>/resources' \
  -H "Authorization: Bearer $HYDRADB_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "resource_id": "C01ABC123",
    "resource_type": "channel",
    "display_name": "general"
  }'
```

### 5. Trigger the first sync

Connectors sync automatically on schedule, but you can trigger an immediate sync:

```bash cURL
curl -X POST 'https://api.hydradb.com/v2/connectors/<connector_id>/sync' \
  -H "Authorization: Bearer $HYDRADB_API_KEY"
```

**Response:**

```json
{
  "workflow_id": "connector-sync-abc123",
  "run_id": "run-xyz789"
}
```

## Setting up a Gmail connector

Gmail connectors sync email messages from selected labels into HydraDB. You need a Google Cloud project with OAuth credentials.

### Prerequisites

1. Create a project in [Google Cloud Console](https://console.cloud.google.com/).
2. Enable the Gmail API for your project.
3. Configure an OAuth consent screen (internal for Google Workspace, or external for general use).
4. Create OAuth 2.0 credentials and obtain an access token with the required scope.

### Required OAuth scope

Your OAuth token must include at least one of these scopes:

| Scope | Access level |
|---|---|
| `https://www.googleapis.com/auth/gmail.readonly` | Read-only access to Gmail (recommended) |
| `https://mail.google.com/` | Full access to Gmail |

<Tip>
Use the `gmail.readonly` scope for most integrations. It provides read access to messages without the ability to modify or delete emails.
</Tip>

### 1. Create the connector

```bash cURL
curl -X POST 'https://api.hydradb.com/v2/connectors' \
  -H "Authorization: Bearer $HYDRADB_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "gmail",
    "tenant_id": "my_tenant",
    "auth_type": "api_token",
    "credentials": {
      "api_token": "ya29.your-google-oauth-token"
    }
  }'
```

The response includes a `connector_id` you'll use for subsequent calls.

### 2. Discover available labels

Discover which Gmail labels are available to sync:

```bash cURL
curl 'https://api.hydradb.com/v2/connectors/<connector_id>/discover' \
  -H "Authorization: Bearer $HYDRADB_API_KEY"
```

**Response:**

```json
{
  "resources": [
    {
      "id": "INBOX",
      "name": "INBOX",
      "resource_type": "label",
      "metadata": {
        "type": "system",
        "hidden": false
      }
    },
    {
      "id": "Label_1",
      "name": "Work",
      "resource_type": "label",
      "metadata": {
        "type": "user",
        "hidden": false
      }
    }
  ]
}
```

Gmail labels include system labels (INBOX, SENT, DRAFTS) and user-created labels.

### 3. Add labels as resources

For each label you want to sync, create a resource:

```bash cURL
curl -X POST 'https://api.hydradb.com/v2/connectors/<connector_id>/resources' \
  -H "Authorization: Bearer $HYDRADB_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "resource_id": "INBOX",
    "resource_type": "label",
    "display_name": "Inbox"
  }'
```

You can also configure multiple labels at once using the configure endpoint:

```bash cURL
curl -X POST 'https://api.hydradb.com/v2/connectors/<connector_id>/configure' \
  -H "Authorization: Bearer $HYDRADB_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "lookback_days": 30,
    "resources": [
      {
        "resource_id": "INBOX",
        "resource_type": "label",
        "name": "Inbox"
      },
      {
        "resource_id": "Label_1",
        "resource_type": "label",
        "name": "Work"
      }
    ]
  }'
```

### 4. Trigger the first sync

```bash cURL
curl -X POST 'https://api.hydradb.com/v2/connectors/<connector_id>/sync' \
  -H "Authorization: Bearer $HYDRADB_API_KEY"
```

### What gets synced

Gmail connectors sync email messages with the following fields:

| Field | Description |
|---|---|
| `subject` | Email subject line |
| `body` | Email body content (decoded from the message payload) |
| `from` | Sender email address |
| `to` | Recipient email address |
| `cc` | CC recipients |
| `reply_to` | Reply-To address (if set) |
| `in_reply_to` | RFC 2822 Message-ID of the parent email (for threading) |
| `thread_id` | Gmail thread identifier (groups related messages) |
| `created_at` | When the email was received |

**Attachments** are extracted automatically. Each attachment includes its filename, content type, and size.

**Threading**: When an email is a reply, HydraDB resolves the `In-Reply-To` header to link it to the parent message. This creates a `reply_to` relation in the graph, so you can run thread-aware queries.

Synced messages use `kind: "email"` and `provider: "gmail"`, so you can filter by provider in your queries.

## Setting up a Notion connector

Notion connectors sync page content from your Notion workspace. You can select entire databases (syncing all pages within them) or individual top-level pages.

### 1. Create an internal integration

1. Go to [notion.so/my-integrations](https://www.notion.so/my-integrations) and create a new integration.
2. Select the workspace you want to connect.
3. Under **Capabilities**, enable **Read content**.
4. Copy the **Internal Integration Secret** (starts with `ntn_` or `secret_`).

### 2. Share content with your integration

Notion integrations can only access pages and databases explicitly shared with them:

1. Open the database or page you want to sync.
2. Click **Share** in the top right.
3. Select your integration from the **Invite** dropdown.

<Note>
When you share a database, all pages inside it become accessible. When you share a top-level page, only that specific page is synced.
</Note>

### 3. Create the connector

```bash cURL
curl -X POST 'https://api.hydradb.com/v2/connectors' \
  -H "Authorization: Bearer $HYDRADB_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "notion",
    "tenant_id": "my_tenant",
    "auth_type": "api_token",
    "credentials": {
      "api_token": "ntn_your_notion_integration_secret"
    }
  }'
```

### 4. Discover databases and pages

The discover endpoint returns all databases and top-level pages shared with your integration:

```bash cURL
curl 'https://api.hydradb.com/v2/connectors/<connector_id>/discover' \
  -H "Authorization: Bearer $HYDRADB_API_KEY"
```

**Response:**

```json
{
  "databases": [
    {
      "id": "abc123-def456",
      "name": "Product Docs",
      "resource_type": "notion_database",
      "metadata": {
        "url": "https://notion.so/abc123"
      }
    }
  ],
  "pages": [
    {
      "id": "xyz789-uvw012",
      "name": "Company Handbook",
      "resource_type": "notion_page",
      "metadata": {
        "url": "https://notion.so/xyz789"
      }
    }
  ]
}
```

### 5. Add resources to sync

Add databases or pages as resources. Use `notion_database` or `notion_page` as the resource type:

```bash cURL
curl -X POST 'https://api.hydradb.com/v2/connectors/<connector_id>/resources' \
  -H "Authorization: Bearer $HYDRADB_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "resource_id": "abc123-def456",
    "resource_type": "notion_database",
    "display_name": "Product Docs"
  }'
```

| Resource type | Behavior |
|---|---|
| `notion_database` | Syncs all pages within the database, tracking changes by last edited time |
| `notion_page` | Syncs a single top-level page |

### 6. Trigger the first sync

```bash cURL
curl -X POST 'https://api.hydradb.com/v2/connectors/<connector_id>/sync' \
  -H "Authorization: Bearer $HYDRADB_API_KEY"
```

### What gets synced

HydraDB extracts content from Notion pages, including:

- Paragraph text
- Headings (H1, H2, H3)
- Bulleted and numbered lists
- To-do items
- Quotes and callouts
- Images and file attachments

**Attachments** embedded in pages (images and files) are extracted automatically. Each attachment includes its URL and content type.

Synced pages appear with `kind: "knowledge_base"` and `provider: "notion"` in recall results.

## Setting up a GitHub connector

The GitHub connector syncs issues from repositories you have access to. Each issue becomes a searchable record containing its title, body, author, state, and timestamps.

<Note>
The GitHub connector syncs issues only, not pull requests. Pull requests are filtered out during ingestion.
</Note>

### 1. Create a GitHub Personal Access Token

1. Go to [github.com/settings/tokens](https://github.com/settings/tokens) and create a new token.
2. Select the scopes your token needs:

| Scope | Purpose |
|---|---|
| `repo` | Access to all repositories (public and private) |
| `public_repo` | Access to public repositories only |

3. Copy the generated token (starts with `ghp_` for classic tokens).

<Tip>
Fine-grained personal access tokens also work. Grant repository access to the specific repos you want to sync and ensure the token has read access to issues.
</Tip>

### 2. Create the connector

```bash cURL
curl -X POST 'https://api.hydradb.com/v2/connectors' \
  -H "Authorization: Bearer $HYDRADB_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "github",
    "tenant_id": "my_tenant",
    "auth_type": "api_token",
    "credentials": {
      "api_token": "ghp_your-github-token"
    }
  }'
```

### 3. Discover available repositories

List repositories the token has access to:

```bash cURL
curl 'https://api.hydradb.com/v2/connectors/<connector_id>/discover' \
  -H "Authorization: Bearer $HYDRADB_API_KEY"
```

**Response:**

```json
{
  "repositories": [
    {
      "id": "octocat/hello-world",
      "name": "hello-world",
      "resource_type": "repository",
      "metadata": {
        "private": false,
        "description": "My first repository"
      }
    },
    {
      "id": "octocat/private-project",
      "name": "private-project",
      "resource_type": "repository",
      "metadata": {
        "private": true,
        "description": "Internal tooling"
      }
    }
  ]
}
```

The `id` field uses the `owner/repo` format, which you'll use as the `resource_id` when adding repositories.

### 4. Add repositories as resources

For each repository you want to sync:

```bash cURL
curl -X POST 'https://api.hydradb.com/v2/connectors/<connector_id>/resources' \
  -H "Authorization: Bearer $HYDRADB_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "resource_id": "octocat/hello-world",
    "resource_type": "repository",
    "display_name": "hello-world"
  }'
```

### 5. Trigger the first sync

```bash cURL
curl -X POST 'https://api.hydradb.com/v2/connectors/<connector_id>/sync' \
  -H "Authorization: Bearer $HYDRADB_API_KEY"
```

Synced issues appear with `kind: "ticket"` and `provider: "github"` in recall results.

## Setting up a Linear connector

Linear connectors sync issues from your Linear workspace. You can select entire teams (syncing all issues within them) or specific projects.

### 1. Create an API key

1. In Linear, go to **Settings → API** (or navigate to [linear.app/settings/api](https://linear.app/settings/api)).
2. Create a new personal API key or workspace API key.
3. Copy the key (starts with `lin_api_`).

<Tip>
Personal API keys inherit the user's permissions. For production use, consider using a service account or workspace-level key with the minimum required access.
</Tip>

### 2. Create the connector

```bash cURL
curl -X POST 'https://api.hydradb.com/v2/connectors' \
  -H "Authorization: Bearer $HYDRADB_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "linear",
    "tenant_id": "my_tenant",
    "auth_type": "api_token",
    "credentials": {
      "api_token": "lin_api_your_api_key"
    }
  }'
```

### 3. Discover teams and projects

The discover endpoint returns teams and projects accessible with your API key:

```bash cURL
curl 'https://api.hydradb.com/v2/connectors/<connector_id>/discover' \
  -H "Authorization: Bearer $HYDRADB_API_KEY"
```

**Response:**

```json
{
  "teams": [
    {
      "id": "team-uuid-123",
      "name": "Engineering",
      "resource_type": "linear_team",
      "metadata": { "key": "ENG" }
    }
  ],
  "projects": [
    {
      "id": "project-uuid-456",
      "name": "Q2 Launch",
      "resource_type": "linear_project",
      "metadata": {
        "slug": "q2-launch",
        "team_name": "Engineering"
      }
    }
  ]
}
```

### 4. Configure resources to sync

Use the configure endpoint to add teams or projects with a lookback period:

```bash cURL
curl -X POST 'https://api.hydradb.com/v2/connectors/<connector_id>/configure' \
  -H "Authorization: Bearer $HYDRADB_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "lookback_days": 30,
    "resources": [
      {
        "resource_id": "team-uuid-123",
        "name": "Engineering",
        "resource_type": "linear_team"
      },
      {
        "resource_id": "project-uuid-456",
        "name": "Q2 Launch",
        "resource_type": "linear_project"
      }
    ]
  }'
```

| Resource type | Behavior |
|---|---|
| `linear_team` | Syncs all issues belonging to the team |
| `linear_project` | Syncs all issues in a specific project |

<Note>
Issues are synced based on their `updatedAt` timestamp. The initial sync fetches issues updated within `lookback_days`. Subsequent syncs fetch only newly updated issues.
</Note>

### What gets synced

HydraDB syncs issue content from Linear, including:

- Issue title and description
- State, priority, and labels
- Assignee and creator information
- Team and project context

Synced issues appear with `kind: "ticket"` and `provider: "linear"` in recall results.

## Sync behavior

### Initial sync lookback

On the first sync, HydraDB fetches data from the last 30 days by default. You can customize this with a filter when creating the resource:

```json
{
  "resource_id": "C01ABC123",
  "resource_type": "channel",
  "display_name": "general",
  "filters": {
    "lookback_days": 7
  }
}
```

### Incremental syncs

After the initial sync, HydraDB tracks a cursor for each resource. Subsequent syncs fetch only new or updated records since the last run.

### Sync interval

The default sync interval is 30 minutes. You can set a custom interval (in seconds) when creating the connector:

```json
{
  "provider": "slack",
  "tenant_id": "my_tenant",
  "sync_interval_seconds": 3600,
  "credentials": { ... }
}
```

## Authentication types

Connectors support three authentication types:

| Type | When to use |
|---|---|
| `api_token` | Single token authentication (Slack bot tokens, Gmail OAuth tokens, GitHub PATs, Linear API keys) |
| `client_secret` | OAuth client credentials flow |
| `static_bundle` | Multiple credential fields together |

Slack, Gmail, Notion, GitHub, and Linear all use `api_token` authentication.

## Querying connector data

Once synced, connector data appears in recall results when you include `search_apps: true`:

```bash cURL
curl -X POST 'https://api.hydradb.com/recall/full_recall' \
  -H "Authorization: Bearer $HYDRADB_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "tenant_id": "my_tenant",
    "query": "What did the team discuss about the auth rollback?",
    "search_apps": true
  }'
```

Data from connectors includes a `provider` field you can filter on:

| Provider | kind | provider |
|---|---|---|
| Slack | `message` | `slack` |
| Gmail | `email` | `gmail` |
| Notion | `knowledge_base` | `notion` |
| GitHub | `ticket` | `github` |
| Linear | `ticket` | `linear` |

## Managing connectors

### List connectors

```bash cURL
curl 'https://api.hydradb.com/v2/connectors' \
  -H "Authorization: Bearer $HYDRADB_API_KEY"
```

### Get connector details

```bash cURL
curl 'https://api.hydradb.com/v2/connectors/<connector_id>' \
  -H "Authorization: Bearer $HYDRADB_API_KEY"
```

### List resources

```bash cURL
curl 'https://api.hydradb.com/v2/connectors/<connector_id>/resources' \
  -H "Authorization: Bearer $HYDRADB_API_KEY"
```

### Delete a resource

```bash cURL
curl -X DELETE 'https://api.hydradb.com/v2/connectors/<connector_id>/resources/<resource_id>' \
  -H "Authorization: Bearer $HYDRADB_API_KEY"
```

### Delete a connector

Deleting a connector removes all its resources and credentials:

```bash cURL
curl -X DELETE 'https://api.hydradb.com/v2/connectors/<connector_id>' \
  -H "Authorization: Bearer $HYDRADB_API_KEY"
```
