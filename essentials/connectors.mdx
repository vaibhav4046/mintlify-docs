Connectors let you sync data from third-party applications directly into HydraDB. Configure a connector once, and HydraDB handles authentication, pagination, and incremental syncing.

Use connectors when you want to:

- Ingest Slack messages, Gmail emails, or Notion pages automatically
- Sync GitHub issues from repositories for searchable project context
- Sync Linear issues from teams or projects
- Keep HydraDB in sync with external data sources on a schedule
- Avoid writing custom polling or webhook infrastructure

## Supported providers

| Provider | Data synced | Authentication |
|---|---|---|
| **Slack** | Messages from selected channels | Bot token (`xoxb-`) or user token (`xoxp-`) |
| **Gmail** | Emails from selected mailboxes | App Password via IMAP |
| **Notion** | Pages from selected databases or top-level pages | Internal integration token |
| **GitHub** | Issues and pull requests from repositories | Personal access token (`ghp_`) |
| **Linear** | Issues from selected teams or projects | API key (`lin_api_`) |

---

## How connectors work

A connector is a link between HydraDB and an external application. You provide credentials (an API token), select which resources to sync (such as Slack channels, Gmail labels, or Notion databases), and HydraDB handles the rest.

```mermaid

  D --> E[Sync Runs]
```

Each connector has:

| Component | Description |
|---|---|
| **Provider** | The external application (Slack, Gmail, or Notion) |
| **Credentials** | Authentication for the provider (API token) |
| **Resources** | Individual data sources within the provider (Slack channels, Gmail labels, Notion databases) |
| **Sync schedule** | How often HydraDB pulls new data (default: 30 minutes) |

## Connector vs app sources

Connectors and [app sources](/essentials/app-sources) serve different purposes:

| Approach | When to use |
|---|---|
| **Connectors** | HydraDB pulls data automatically from a supported provider |
| **App sources** | You push data to HydraDB from your own backend or a provider we don't yet support |

Connectors produce app-source records internally. Once synced, connector data is searchable via `search_apps: true` just like manually ingested app sources.

## Using the dashboard

The dashboard provides a visual interface for connecting any supported provider. Navigate to **Connectors** in the sidebar at [app.hydradb.com](https://app.hydradb.com) to get started.

### Connecting a provider

Each provider card shows the data types it syncs (for example, "Channels · Threads · Messages" for Slack). Click **Connect** to open the connection form.

| Field | Description |
|---|---|
| **Target tenant** | Select which tenant owns this connector |
| **Credentials** | The authentication token for the provider (see provider-specific sections below for how to obtain tokens) |

The form validates your credentials before saving. Once valid, click **Establish connection** to create the connector.

### Adding resources to sync

After connecting, expand the connector row and click **Add** to open the resource picker. The picker discovers available resources from the provider (Slack channels, Gmail mailboxes, GitHub repositories, Notion databases, or Linear teams).

Select the resources you want to sync, then configure:

**Tenant routing**

| Option | Behavior |
|---|---|
| **All resources → connector tenant** | All selected resources sync to the connector's tenant |
| **Route specific resources to different tenants** | Assign individual resources to different tenants |

**Sub-tenant mapping**

| Option | Behavior |
|---|---|
| **Per resource** | Each resource becomes its own sub-tenant (named after the resource) |
| **Single** | All selected resources share one sub-tenant you specify |
| **Custom** | Set a custom sub-tenant name for each resource individually |

**History window**

Choose how far back to sync on the initial import:

| Option | Description |
|---|---|
| **Last 30 days** | Default lookback period |
| **Last 3 months** | Sync 90 days of history |
| **Last 6 months** | Sync 180 days of history |
| **Last year** | Sync 365 days of history |
| **From the beginning** | Sync all available history |
| **Custom** | Specify a custom lookback time in hours, days, or months |

<Note>
History older than 30 days is backfilled in the background after the initial sync completes. When using a custom lookback in hours, the value is converted to whole days (minimum 1 day).
</Note>

Click **Add resources** to start syncing.

### Managing connectors

From the connectors page you can:

- **Trigger sync** — Start an immediate sync instead of waiting for the schedule
- **View resources** — Expand a connector to see its synced resources
- **Remove resources** — Delete individual resources from a connector
- **Delete connector** — Remove the connector entirely (previously synced data remains in HydraDB)

## Setting up a Slack connector

You can set up a Slack connector using the dashboard or the API. See [Using the dashboard](#using-the-dashboard) for the visual setup flow.

### Using the API

For programmatic setup or automation, use the Connectors API directly.

### 1. Create a Slack app

1. Go to [api.slack.com/apps](https://api.slack.com/apps) and create a new app.
2. Under **OAuth & Permissions**, add these bot token scopes:

| Scope | Purpose |
|---|---|
| `channels:read` | List public channels |
| `channels:history` | Read messages from public channels |
| `groups:read` | List private channels the bot is in |
| `groups:history` | Read messages from private channels |

3. Install the app to your workspace.
4. Copy the **Bot User OAuth Token** (starts with `xoxb-`).

### 2. Create the connector

```bash cURL
curl -X POST 'https://api.hydradb.com/v2/connectors' \
  -H "Authorization: Bearer $HYDRADB_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "slack",
    "tenant_id": "my_tenant",
    "auth_type": "api_token",
    "credentials": {
      "api_token": "xoxb-your-slack-bot-token"
    }
  }'
```

The response includes a `connector_id` you'll use for subsequent calls.

### 3. Discover available channels

Before adding resources, discover which channels the bot can access:

```bash cURL
curl 'https://api.hydradb.com/v2/connectors/<connector_id>/discover' \
  -H "Authorization: Bearer $HYDRADB_API_KEY"
```

**Response:**

```json
{
  "channels": [
    {
      "id": "C01ABC123",
      "name": "general",
      "is_private": false,
      "is_member": true,
      "num_members": 42
    },
    {
      "id": "C02DEF456",
      "name": "engineering",
      "is_private": false,
      "is_member": true,
      "num_members": 15
    }
  ]
}
```

<Note>
The bot must be a member of private channels to see them in the discover response. Invite the bot to any private channels you want to sync.
</Note>

### 4. Add channels as resources

For each channel you want to sync, create a resource:

```bash cURL
curl -X POST 'https://api.hydradb.com/v2/connectors/<connector_id>/resources' \
  -H "Authorization: Bearer $HYDRADB_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "resource_id": "C01ABC123",
    "resource_type": "channel",
    "display_name": "general"
  }'
```

### 5. Trigger the first sync

Connectors sync automatically on schedule, but you can trigger an immediate sync:

```bash cURL
curl -X POST 'https://api.hydradb.com/v2/connectors/<connector_id>/sync' \
  -H "Authorization: Bearer $HYDRADB_API_KEY"
```

**Response:**

```json
{
  "workflow_id": "connector-sync-abc123",
  "run_id": "run-xyz789"
}
```

### What gets synced

Slack connectors sync messages with the following fields:

| Field | Description |
|---|---|
| `body` | Message text content |
| `author` | Display name of the message sender (resolved from Slack user profiles) |
| `thread_id` | Thread timestamp (groups thread replies together) |
| `parent_id` | Parent message timestamp (for thread replies) |
| `created_at` | When the message was posted |
| `edited` | Timestamp of the last edit (if the message was edited) |
| `edited_by` | Display name of the user who last edited the message |
| `url` | Permalink to the message |

**Threading**: Slack threads are grouped as single documents containing the parent message and all replies. Each message includes `thread_id` pointing to the thread root and `parent_id` pointing to the immediate parent.

**Author resolution**: The connector resolves Slack user IDs to display names, so queries like "messages from Alice" work correctly.

Synced messages use `kind: "message"` and `provider: "slack"`. You can filter by provider in your queries.

## Setting up a Gmail connector

Gmail connectors sync email messages from selected mailboxes into HydraDB using IMAP with an App Password. You can set up a Gmail connector using the [dashboard](#using-the-dashboard) or the API.

### Prerequisites

The Gmail connector uses IMAP authentication with an App Password. This requires:

1. A Gmail account with [2-Step Verification](https://myaccount.google.com/signinoptions/two-step-verification) enabled.
2. An App Password generated specifically for HydraDB.

<Warning>
App Passwords are only available when 2-Step Verification is enabled on your Google account. If you see an error about App Passwords not being available, enable 2-Step Verification first.
</Warning>

### 1. Generate an App Password

1. Go to [myaccount.google.com/apppasswords](https://myaccount.google.com/apppasswords).
2. Sign in if prompted.
3. Enter a name for the app (e.g., "HydraDB").
4. Click **Create**.
5. Copy the 16-character password (shown with spaces, but spaces are optional when using it).

<Tip>
App Passwords look like `abcd wxyz efgh ijkl`. You can use them with or without spaces. Store the password securely — Google only shows it once.
</Tip>

### 2. Create the connector

#### Using the dashboard

The Gmail connector form has two fields:

| Field | Description |
|---|---|
| **Gmail address** | Your Gmail email address (e.g., `you@gmail.com`) |
| **App password** | The 16-character App Password from step 1 |

Enter your Gmail address and App Password, then click **Establish connection**.

#### Using the API

When using the API directly, provide credentials in `email:app_password` format:

```bash cURL
curl -X POST 'https://api.hydradb.com/v2/connectors' \
  -H "Authorization: Bearer $HYDRADB_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "gmail",
    "tenant_id": "my_tenant",
    "auth_type": "api_token",
    "credentials": {
      "access_token": "user@gmail.com:abcdwxyzefghijkl"
    }
  }'
```

The `access_token` field should contain your Gmail address followed by a colon and your App Password (no spaces).

### 3. Discover available mailboxes

Discover which IMAP mailboxes are available to sync:

```bash cURL
curl 'https://api.hydradb.com/v2/connectors/<connector_id>/discover' \
  -H "Authorization: Bearer $HYDRADB_API_KEY"
```

**Response:**

```json
{
  "resources": [
    {
      "id": "INBOX",
      "name": "INBOX",
      "resource_type": "gmail_label"
    },
    {
      "id": "[Gmail]/Sent Mail",
      "name": "[Gmail]/Sent Mail",
      "resource_type": "gmail_label"
    },
    {
      "id": "Work",
      "name": "Work",
      "resource_type": "gmail_label"
    }
  ]
}
```

The discover endpoint returns all IMAP-selectable mailboxes, including system folders (INBOX, Sent Mail) and custom labels.

### 4. Add mailboxes as resources

For each mailbox you want to sync, create a resource:

```bash cURL
curl -X POST 'https://api.hydradb.com/v2/connectors/<connector_id>/resources' \
  -H "Authorization: Bearer $HYDRADB_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "resource_id": "INBOX",
    "resource_type": "gmail_label",
    "display_name": "Inbox"
  }'
```

You can also configure multiple mailboxes at once using the configure endpoint:

```bash cURL
curl -X POST 'https://api.hydradb.com/v2/connectors/<connector_id>/configure' \
  -H "Authorization: Bearer $HYDRADB_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "lookback_days": 10,
    "resources": [
      {
        "resource_id": "INBOX",
        "resource_type": "gmail_label",
        "name": "Inbox"
      },
      {
        "resource_id": "Work",
        "resource_type": "gmail_label",
        "name": "Work"
      }
    ]
  }'
```

### 5. Trigger the first sync

```bash cURL
curl -X POST 'https://api.hydradb.com/v2/connectors/<connector_id>/sync' \
  -H "Authorization: Bearer $HYDRADB_API_KEY"
```

### What gets synced

Gmail connectors sync email messages with the following fields:

| Field | Description |
|---|---|
| `subject` | Email subject line |
| `body` | Email body content (plain text extracted from MIME parts) |
| `from` | Sender email address with display name |
| `to` | Recipient email addresses |
| `cc` | CC recipients |
| `reply_to` | Reply-To address (if set) |
| `in_reply_to` | RFC 2822 Message-ID of the parent email (for threading) |
| `message_id` | RFC 2822 Message-ID of this email |
| `thread_id` | Thread identifier (groups related messages) |
| `created_at` | When the email was received |

**Full thread ingestion**: When a recent email belongs to a thread, the connector fetches all messages in that thread (including older messages outside the lookback window) so the complete conversation is ingested together.

**MIME handling**: The connector handles multipart emails correctly, preferring plain text over HTML and properly decoding quoted-printable and base64 transfer encodings.

**Threading**: The connector uses `In-Reply-To` and `References` headers to resolve parent messages and build the full reply chain. This creates `reply_to` relations in the graph for thread-aware queries.

Synced messages use `kind: "email"` and `provider: "gmail"`, so you can filter by provider in your queries.

## Setting up a Notion connector

Notion connectors sync page content from your Notion workspace. You can select entire databases (syncing all pages within them) or individual top-level pages. You can set up a Notion connector using the [dashboard](#using-the-dashboard) or the API.

### 1. Create an internal integration

1. Go to [notion.so/my-integrations](https://www.notion.so/my-integrations) and create a new integration.
2. Select the workspace you want to connect.
3. Under **Capabilities**, enable **Read content**.
4. Copy the **Internal Integration Secret** (starts with `ntn_` or `secret_`).

### 2. Share content with your integration

Notion integrations can only access pages and databases explicitly shared with them:

1. Open the database or page you want to sync.
2. Click **Share** in the top right.
3. Select your integration from the **Invite** dropdown.

<Note>
When you share a database, all pages inside it become accessible. When you share a top-level page, only that specific page is synced.
</Note>

### 3. Create the connector

```bash cURL
curl -X POST 'https://api.hydradb.com/v2/connectors' \
  -H "Authorization: Bearer $HYDRADB_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "notion",
    "tenant_id": "my_tenant",
    "auth_type": "api_token",
    "credentials": {
      "api_token": "ntn_your_notion_integration_secret"
    }
  }'
```

### 4. Discover databases and pages

The discover endpoint returns all databases and top-level pages shared with your integration:

```bash cURL
curl 'https://api.hydradb.com/v2/connectors/<connector_id>/discover' \
  -H "Authorization: Bearer $HYDRADB_API_KEY"
```

**Response:**

```json
{
  "databases": [
    {
      "id": "abc123-def456",
      "name": "Product Docs",
      "resource_type": "notion_database",
      "metadata": {
        "url": "https://notion.so/abc123"
      }
    }
  ],
  "pages": [
    {
      "id": "xyz789-uvw012",
      "name": "Company Handbook",
      "resource_type": "notion_page",
      "metadata": {
        "url": "https://notion.so/xyz789"
      }
    }
  ]
}
```

### 5. Add resources to sync

Add databases or pages as resources. Use `notion_database` or `notion_page` as the resource type:

```bash cURL
curl -X POST 'https://api.hydradb.com/v2/connectors/<connector_id>/resources' \
  -H "Authorization: Bearer $HYDRADB_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "resource_id": "abc123-def456",
    "resource_type": "notion_database",
    "display_name": "Product Docs"
  }'
```

| Resource type | Behavior |
|---|---|
| `notion_database` | Syncs all pages within the database, tracking changes by last edited time |
| `notion_page` | Syncs a single top-level page |

### 6. Trigger the first sync

```bash cURL
curl -X POST 'https://api.hydradb.com/v2/connectors/<connector_id>/sync' \
  -H "Authorization: Bearer $HYDRADB_API_KEY"
```

### What gets synced

HydraDB extracts content from Notion pages, including:

- Paragraph text
- Headings (H1, H2, H3)
- Bulleted and numbered lists
- To-do items
- Quotes and callouts
- Images and file attachments

**Attachments** embedded in pages (images and files) are extracted automatically. Each attachment includes its URL and content type.

Synced pages appear with `kind: "knowledge_base"` and `provider: "notion"` in recall results.

## Setting up a GitHub connector

The GitHub connector syncs issues and pull requests from repositories you have access to. Each item becomes a searchable record containing its title, body, author, state, and timestamps. You can set up a GitHub connector using the [dashboard](#using-the-dashboard) or the API.

1. Go to [github.com/settings/tokens](https://github.com/settings/tokens) and create a new token.
2. Select the scopes your token needs:

| Scope | Purpose |
|---|---|
| `repo` | Access to all repositories (public and private) |
| `public_repo` | Access to public repositories only |

3. Copy the generated token (starts with `ghp_` for classic tokens).

<Tip>
Fine-grained personal access tokens also work. Grant repository access to the specific repos you want to sync and ensure the token has read access to issues.
</Tip>

### 2. Create the connector

```bash cURL
curl -X POST 'https://api.hydradb.com/v2/connectors' \
  -H "Authorization: Bearer $HYDRADB_API_KEY" \

    "provider": "github",
    "tenant_id": "my_tenant",
    "auth_type": "api_token",
    "credentials": {
      "api_token": "ghp_your-github-token"
    }
  }'
```

### 3. Discover available repositories

List repositories the token has access to:

```bash cURL
curl 'https://api.hydradb.com/v2/connectors/<connector_id>/discover' \
```

GitHub connectors sync issues and pull requests with the following fields:

| Field | Description |
|---|---|

| `author` | GitHub username of the creator |
| `state` | State (`open` or `closed`) |
| `assignees` | List of assigned GitHub usernames |
| `labels` | Labels |
| `milestone` | Milestone name (if assigned) |
| `is_pr` | `true` for pull requests, `false` for issues |
| `created_at` | When the item was created |
| `updated_at` | When the item was last updated |
| `closed_at` | When the item was closed (if applicable) |
| `url` | Direct link to the issue or PR on GitHub |

Both issues and pull requests use `kind: "ticket"` and `provider: "github"`. Use the `is_pr` field to distinguish between them in queries.

```bash cURL
        "resource_id": "team-uuid-123",
        "name": "Engineering",

        "resource_id": "project-uuid-456",
```

| Resource type | Behavior |

| `linear_project` | Syncs all issues in a specific project |

Issues are synced based on their `updatedAt` timestamp. The initial sync fetches issues updated within `lookback_days`. Subsequent syncs fetch only newly updated issues.
</Note>

HydraDB syncs issue content from Linear, including:

- Issue title and description
- State, priority, and labels
- Assignee and creator information
- Team and project context

Synced issues appear with `kind: "ticket"` and `provider: "linear"` in recall results.

## Sync behavior

### Initial sync lookback

On the first sync, HydraDB fetches data from the last 30 days by default. You can customize this with a filter when creating the resource:

```json
{
  "resource_id": "C01ABC123",
  "resource_type": "channel",
  "display_name": "general",
  "filters": {
    "lookback_days": 7
  }
}
```

### Incremental syncs

After the initial sync, HydraDB tracks a cursor for each resource. Subsequent syncs fetch only new or updated records since the last run.

This holds even when the first sync returns no records. If a resource has no activity within its lookback window (for example, an inactive GitHub repository), HydraDB still advances the cursor to the sync time. Later syncs then pick up only new activity instead of re-scanning the full lookback window each time.

### Reconfiguring resources

Reconfiguring an existing resource updates its settings without resetting its cursor. Sync progress is preserved, so records you've already synced aren't re-ingested.

If you extend a resource's history window while a background backfill is still running, the new window takes effect reliably. The updated backfill target is preserved even if the in-flight backfill finishes at the same time.

### Sync interval

The default sync interval is 30 minutes. You can set a custom interval (in seconds) when creating the connector:

```json
{
  "provider": "slack",
  "tenant_id": "my_tenant",
  "sync_interval_seconds": 3600,
  "credentials": { ... }
}
```

## Authentication types

Connectors support two authentication types:

| Type | When to use |
|---|---|
| `api_token` | Single token authentication (Slack bot tokens, Gmail App Passwords, GitHub PATs, Linear API keys) |
| `static_bundle` | Multiple credential fields together |

All supported providers (Slack, Gmail, Notion, GitHub, and Linear) use `api_token` authentication.

## Querying connector data

Once synced, connector data appears in recall results when you include `search_apps: true`:

```bash cURL
curl -X POST 'https://api.hydradb.com/recall/full_recall' \
  -H "Authorization: Bearer $HYDRADB_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "tenant_id": "my_tenant",
    "query": "What did the team discuss about the auth rollback?",
    "search_apps": true
  }'
```

Data from connectors includes a `provider` field you can filter on:

| Provider | kind | provider |
|---|---|---|
| Slack | `message` | `slack` |
| Gmail | `email` | `gmail` |
| Notion | `knowledge_base` | `notion` |
| GitHub | `ticket` | `github` |
| Linear | `ticket` | `linear` |

## Managing connectors

### List connectors

```bash cURL
curl 'https://api.hydradb.com/v2/connectors' \
  -H "Authorization: Bearer $HYDRADB_API_KEY"
```

### Get connector details

```bash cURL
curl 'https://api.hydradb.com/v2/connectors/<connector_id>' \
  -H "Authorization: Bearer $HYDRADB_API_KEY"
```

### List resources

```bash cURL
curl 'https://api.hydradb.com/v2/connectors/<connector_id>/resources' \
  -H "Authorization: Bearer $HYDRADB_API_KEY"
```

### Delete a resource

```bash cURL
curl -X DELETE 'https://api.hydradb.com/v2/connectors/<connector_id>/resources/<resource_id>' \
  -H "Authorization: Bearer $HYDRADB_API_KEY"
```

### Delete a connector

Deleting a connector removes all its resources and credentials:

```bash cURL
curl -X DELETE 'https://api.hydradb.com/v2/connectors/<connector_id>' \
  -H "Authorization: Bearer $HYDRADB_API_KEY"
```
