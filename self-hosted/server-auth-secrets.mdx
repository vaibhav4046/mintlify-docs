---
title: "Server Authentication Secrets"
description: "Required authentication secrets for HydraDB server deployments"
---

Self-hosted HydraDB deployments require three authentication secrets. The server validates these at startup and exits if any are missing.

## Required Environment Variables

| Variable | Description |
|----------|-------------|
| `NEXTAUTH_SECRET` | Secret for encrypting NextAuth sessions and tokens |
| `JWT_SECRET_KEY` | HMAC key for signing and verifying JWTs |
| `CORTEX_INTERNAL_SECRET` | Secret for authenticating internal service-to-service requests |

All three are required when `ENV` is set to any value other than `local` (for example, `staging`, `prod`, `production`, or any custom environment name).

<Warning>
Empty or whitespace-only values are rejected. The server performs a trim-and-check validation, so `NEXTAUTH_SECRET=" "` will fail.
</Warning>

## Local Development Exemption

Local development is exempt:

- `ENV=local` — secrets are optional
- `ENV` unset or empty — treated as local, secrets are optional

This allows you to run the server locally without configuring production secrets.

## Generating Secrets

Generate a secure random value for each variable:

```bash
openssl rand -base64 32  # NEXTAUTH_SECRET
openssl rand -base64 32  # JWT_SECRET_KEY
openssl rand -base64 32  # CORTEX_INTERNAL_SECRET
```

Use a unique secret for each — do not reuse values across variables.

## Configuration Examples

### Environment Variables

```bash
ENV=staging
NEXTAUTH_SECRET=your-generated-secret-here
JWT_SECRET_KEY=your-generated-jwt-key-here
CORTEX_INTERNAL_SECRET=your-generated-internal-secret-here
```

### Docker Compose

```yaml
services:
  hydradb:
    image: hydradb/application:latest
    environment:
      ENV: staging
      NEXTAUTH_SECRET: ${NEXTAUTH_SECRET}
      JWT_SECRET_KEY: ${JWT_SECRET_KEY}
      CORTEX_INTERNAL_SECRET: ${CORTEX_INTERNAL_SECRET}
```

### Kubernetes Secret

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: hydradb-auth-secrets
type: Opaque
stringData:
  NEXTAUTH_SECRET: your-generated-secret-here
  JWT_SECRET_KEY: your-generated-jwt-key-here
  CORTEX_INTERNAL_SECRET: your-generated-internal-secret-here
```

Reference the secret in your deployment:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: hydradb
spec:
  template:
    spec:
      containers:
        - name: hydradb
          envFrom:
            - secretRef:
                name: hydradb-auth-secrets
          env:
            - name: ENV
              value: "staging"
```

## Startup Validation

When a required secret is missing, the server logs an error listing all missing variables and exits immediately:

```
missing required environment variables: NEXTAUTH_SECRET, JWT_SECRET_KEY
```

This fail-fast behavior prevents the server from running with insecure defaults. Fix the configuration and restart.

## Security Considerations

- Store secrets in a secrets manager (AWS Secrets Manager, HashiCorp Vault, Kubernetes Secrets) rather than plain environment files
- Rotate secrets periodically and update all service instances
- Use different secrets for each environment (staging vs. production)
- Never commit secrets to version control
